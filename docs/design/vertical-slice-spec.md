# 垂直切片设计规格

状态：骨架已可运行。本文是这一版切片的权威说明；与代码冲突时以本文为准，改代码前先改本文。

## 一、这一版要验证什么

砍到只剩一条能跑通的线索。它要回答四个问题：

1. **刷起来爽不爽** —— 掉落节奏与品质梯度。
2. **垃圾有没有出口** —— 拆解、合成是否消除了满背包的焦虑。
3. **变强感够不够** —— 换一件装备能不能肉眼看出差别。
4. **挂机是不是真的省心** —— 该自动的都自动了，玩家回来只需要做判断。

四个都过了，才谈抽卡、另外两个职业、剧情。

### 做

1 个战士职业 · 1 座 3 层地宫（每层 3 房间 + 1 Boss 房）· 8 种怪 · 1–15 级 ·
8 装备部位 · 18 词条 · 掉落/背包/穿戴/拆解/强化(+9)/合成(3合1)/重铸 ·
挂机 + 三个手动开关 + 离线收益 · 煞气再入

### 不做

抽卡、牧师、法师、剧情文本、多张地图、装备套装、赛季。**不做任何加法。**

## 二、节奏目标

| 时长 | 期望状态 |
|---|---|
| 10 分钟 | 凑齐一身绿 |
| 30 分钟 | 拿到第一件蓝 |
| 2 小时 | 拿到第一件紫 |

## 三、数值

### 掉落（普通怪）

- 12% 掉 1 件装备（约每 8 只怪一件）
- 品质：白 60% / 绿 28% / 蓝 10% / 紫 1.9% / 橙 0.1%
- 精英怪（血量 ×3、伤害 ×1.5、脚下光环）：100% 掉 1–2 件，品质池提升一档
- Boss：掉 3 件，其中必有一件紫
- **财运**：每次击杀 0.5% 触发，本次掉落率 ×5

### 装备

- 基础白值：武器=攻击，头/衣/手=护甲，腰/鞋/戒=生命
- 品质乘数：白 1.0 / 绿 1.15 / 蓝 1.3 / 紫 1.5 / 橙 1.8
- 词条条数：白 0 / 绿 1 / 蓝 2 / 紫 3 / 橙 4
- 装备等级 = 区域等级（一层 5 / 二层 10 / 三层 15），固定不变

### 战斗

- 固定逻辑帧 0.2 秒；渲染插值
- 伤害公式见 [ADR-0002](../adr/0002-divisive-armor-mitigation.md)
- 护甲常数 $K$：一层 50 / 二层 120 / 三层 200
- 等级属性见 [ADR-0003](../adr/0003-item-level-bound-to-zone.md)
- 伤害数字控制在 5 位数以内

### 经济

- 拆解：白 1 / 绿 3 / 蓝 8 / 紫 20 / 橙 50 强化矿
- 重铸石：精英怪 5%、Boss 必掉 2–4 个
- 强化消耗：第 n 级需 `2 + 2n` 矿、`20 + 30n` 金
- 合成：不吃材料，只吃 3 件同部位同品质

## 四、系统

### 煞气

通关一层后自动「再入」，煞气 +1（上限 10）。每点：怪物血量/伤害提升、高品质掉率权重微升（每级 +8%，紫/橙按幂次叠加）。

它解决三件事：永远有「刷哪层」的选择；装备等级固定后回低层永远有价值；给「我变强了没有」一个直接验证手段。

### 挂机

内部每 0.2 秒结算一次，画面流畅插值。玩家默认不操作，能做的事只有三件：

1. 吃不吃药（自动服丹开关）
2. 武学自动放不放（自动武学开关）
3. 要不要再入挖矿（再入按钮）

死亡后进入**中断**状态，必须手动「继续挂机」。见 [ADR-0005](../adr/0005-death-interrupts-farming.md)。

### 武器决定武学

武器决定武学，武学决定技能。**唯一的真相来源是身上武器槽里那件装备**（`weaponKindFromEquipped`），
不另立「当前武器」字段去跟装备抢话。

- 技能栏固定 4 槽：0 普攻（自动）/ 1、2 主动（可排优先级）/ 3 位移保命。
- 换一把武器，四槽整排换掉。拿刀就是断岳斩 / 横扫千军 / 开碑手 / 卸甲势，
  拿剑就是劈山式 / 回风扫叶 / 穿云式 / 游身步。
- 玩家排的技能优先级表**跨武器保留**，只是**顺序偏好**，不是白名单：
  表里一条本武器的招都没有时（旧存档只记了剑招、人却换上了刀），
  照样把当前武器能放的主动技按槽位接着排上来 —— 换装那一刻不会变成站桩。
- 真正的武器过滤在挑技能那一步做（`pickSkill`）—— 拿刀的人不会放出剑招。
- **普攻也吃武器**：没有主动技可放时，用的是当前武器 0 号槽那招的倍率
  （刀 1.15 / 剑 1.0），不是写死的 1。
- 「能不能用」和「占不占槽」是两件事：服丹（`sk_potion`）任何武器都能用，
  但它不占技能栏的槽。两处判定都只准写一次，在 `src/data/skills.ts`。
- `weaponKind` 变化时重置冷却表；换的是同一把武器则不动，免得反复点装备刷 CD。
- 切片只做剑与刀；枪棍、拳套、弓、琴箫、拂尘在数据结构里留着，没有技能数据。

### 自动跑图

一间清完自动进下一间；Boss 房清完自动再入本层（煞气 +1）。**这段是挂机的核心，缺了它挂机会停在第 1 间。**

### 离线收益

只给经验、金币、强化矿，上限 8 小时。**绝不给装备。**

## 五、界面（只要 4 页）

1. **战斗页**：3D 场景 + 血条 + 4 个技能槽（随当前武器整排换）+ 三个开关 + 跳字
2. **背包页**：8 部位格子 + 列表 + **悬停对比**
3. **铁匠页**：强化 / 重铸 / 合成 / 拆解压在一页
4. **角色页**：职业（带武器名）+ 属性总览 + 武学列表（当前武器的四招）+ 战斗记录

**悬停对比是整个游戏使用时间最长的交互**：悬停时直接显示「暴击率 12.3% → 15.1%」的差值，绿升红降。不能让玩家自己算。

## 六、技术硬约束

- 同屏 60 只小怪 @60fps（性能红线）
- 关掉实时阴影，用假阴影贴片
- 怪物用 `InstancedMesh`，一次 draw call
- **任何游戏逻辑代码里不允许出现模型名或贴图名**（外观与数值彻底解耦）
- 装备/词条/怪物/掉落表写成 TS 对象而非 JSON（编译期查错）
- 存档：IndexedDB + 5 分钟自动存档 + `.bak` 备份 + 手动导入导出

> 光照提亮与 CC0 贴图的具体数值、贴图清单与验收标准见 [光照提亮与 CC0 贴图规格](lighting-and-textures.md)。

## 七、目录

```
src/
├── types.ts              共享类型
├── data/                 词条、装备、怪物、层、技能（纯数据）
├── sim/                  逻辑层：rng / loot / stats / world / equip-ops
├── render/               Three.js 灰盒渲染（唯一可以谈外观的地方）
├── ui/                   Preact 界面 + 悬停对比
└── storage/              IndexedDB 存档
```

## 八、验证方式

```bash
pnpm dev        # 开发
pnpm test       # 52 项逻辑测试
pnpm build      # 类型检查 + 打包
```

测试里守住的关键红线：除法减伤永不为 0、词条不越部位、等级战力不超过装备、
同屏怪物 ≤ 60、跳字有上限、挂机不会卡在第一间、死亡不夺装备。
