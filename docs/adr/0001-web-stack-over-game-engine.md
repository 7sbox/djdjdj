# ADR-0001：用 Web 自研 + Three.js，不用现成引擎

- 状态：已接受
- 日期：2026-11-28

## 背景

项目要做固定视角 3D 的武侠刷宝挂机游戏，最终目标是单机，之后可能做网游。考虑过 Unity 6（URP）、Godot 4、Web 自研三条路。

本机探测结果：没有安装 Unity、Godot、.NET SDK；已装 Node 24.15 与 pnpm 9.15。

## 决定

采用 **TypeScript + Vite + Three.js**，UI 用 **Preact**（DOM 而非 canvas 内绘制），逻辑层手写「数据 + 系统函数」分层，不引入 ECS 框架。

## 理由

1. 本项目本质是「刷宝 + 构建」，界面与数据占七成工作量，3D 只占三成。Web 栈在背包、词条对比表这类界面上比引擎内 UGUI 快一个量级。
2. 改数值刷新即可见，迭代成本最低；挂机游戏开个标签页挂着最自然。
3. 将来上 Steam 用 Tauri 包层壳（约 5MB），不阻塞。
4. 逻辑层与渲染层彻底分离，将来搬服务器时扔掉渲染层即可。

## 代价（明确接受）

- 没有 Asset Store，只能用 glTF（Free3D / Sketchfab / Kenney）。
- 没有可视化关卡编辑器，房间用代码搭。
- 同屏怪物有硬上限，必须自建 InstancedMesh + 假阴影 + 合并静态网格这套工具链。
- 同屏 60 只 @60fps 是**性能红线**，从第一天起就用它验证。

## 与本文冲突时

任何「要不要改用 Unity / Godot」的提议都要先推翻本文的三条理由，而不是只比较引擎特性。
